# Historical activity correlation

Correlation is a local review aid. It never identifies an actor, supplies native offense provenance, or transfers scores, AI eligibility, blocks or permanent status to another address. A reviewer accepts related observed behavior, not identity. Shared scanners, NAT/proxies and reassigned addresses remain alternatives even after review.

`correlation-2` indexes saved packet features in SQLite by feature, preparation time and immutable packet ID. Each retrieval looks back 365 days and permits at most five minutes of future preparation clock skew. It reads no more than 64 path ranges, 129 entries per range (128 candidates plus a saturation sentinel), and examines at most 512 saved windows. It returns at most three distinct other addresses by default. The caller cannot substitute features for those saved in the packet. Common root paths, generic actions, sensor names, methods, ASN and policy status cannot retrieve a candidate alone.

Candidates require two distinct non-root shared paths, each supported by saved events in both windows, and weighted overlap of at least 0.45. Path weight is 1, parameter-name structure 0.5, action 0.2. Sensor/method/ownership/sequence weight is zero. This deterministic threshold is deliberately conservative and uncalibrated; it is neither maliciousness nor a linkage probability. An exact shared public scanner can still be a candidate. No independent labeled accuracy is claimed. Single-path or non-HTTP histories abstain under this version, so relevant activity can be missed.

Preparation timestamps determine index eligibility, not event simultaneity or continued ownership. Comparisons display cited event timestamps separately. Sequence features are now constructed only within one source/sensor with a positive gap of at most 15 minutes, and never raise similarity. Clock skew, collector delays and incomplete events can still distort order. No ownership continuity or NAT detection is inferred.

Historical backfill processes at most 200 packets per worker cycle. Both old and new derived index readiness are repaired; native history and replay identities are untouched. While backfill is incomplete the UI says so. Common path ranges can saturate: the most recently prepared 128 postings per path are sampled and older relevant windows may be omitted. Both posting saturation and the pool limit are exposed. These are resource bounds, not exhaustive search guarantees. A pending marker is conservative until a backfill pass finishes.

Each selected relationship saves a first-write immutable comparison snapshot with the retrieval version, current/historical packet and event references, overlap and uncertainty. Existing accepted/rejected review states are preserved. Earlier links without a saved comparison are labeled as earlier matching rules. Upgrading does not silently rescind or validate prior reviews. Saved windows may differ from an address's latest window. Accepted components retain stable group IDs and immutable revisions; split/merge parents and revision observations are navigable, including archived groups. No model output automatically accepts a relationship.

Model input remains bounded by existing 18,000-byte prompt/8,192-token context and single-candidate limits. This change requires no GPU model or additional inference service. Run `python -m pytest -q test_behavior_correlation.py test_behavior_groups.py` for isolated synthetic mechanics and `python test_behavior_correlation.py evaluation.json` for a reproducible 3,002-packet retrieval benchmark. Fixture expectations and fixture reviews are explicitly synthetic, never independent ground truth. Production measurements must use a read-only source and isolated backup; no synthetic live events or forced model verdicts are needed.


## Investigation lease correction (CORR-QA1)

Independent correlation QA exposed a pre-existing activity-cache race, not established as caused by the correlation patch. UI/background claimers sampled the comparison clock before waiting for SQLite's writer lock, then sampled a different timestamp when persisting the lease. Across a second boundary, waiting callers could compare against a newer owner's timestamp, see a negative age and each claim the same IP. A passing opportunistic concurrency run did not exclude this race.

`activity.claim_activity` now samples once after `BEGIN IMMEDIATE` succeeds and persists that same full-precision UTC instant. Fresh cache remains300seconds, pending lease90seconds, and quota comparison/increment stays in the same transaction. Expired crashed owners can recover within budget; pending/cached/budget outcomes do not spend quota. Future-dated records remain invalid rather than permanent leases. The UI fast path now uses the same nonnegative-age bounds as the atomic claim and background path, so a future cache/lease cannot suppress refresh indefinitely. Existing background failure backoff of3600seconds is unchanged.

`python -m pytest -q test_activity_leases.py test_behavior_context.py` runs disposable SQLite tests that force a writer-lock wait and an independently sampled next-second timestamp; no timing-dependent retries or live traffic are required. It also tests eight claimers/one owner, shared quotas across different IPs, exact90/300second boundaries, crashed-owner recovery, future clocks and existing background error/cache backoff. Native scoring, retention, replay provenance, AI scoring, source routing and production services are unchanged.
